> *Every week we build one real AI project together, live, in about 45 minutes. The dojo is free, and beginners are welcome.*

Build & Brew is the NextWork live cohort. Each week the room builds one real, end-to-end AI project together in about 45 minutes, on the NextWork Discord. You can build along or just watch, and you never have to speak. Each build lands in a GitHub repo, finished or not, and the point is plain: practice, and proof you can do the work.

Led by Roy Piring, Build Master. Built on NextWork.

## What each build is

Every project is built from one point of view: the high-performing solutions engineer, someone not confined to one role who is expected to touch all twelve. A build is not a tutorial. You plan it, build it, and prove it works, then present it and teach it back. Three things are drilled in every one until they are reflex:

1. **Design before you build.** The decision records and the diagram come before the code.
2. **Prove it or it did not happen.** Every build ends in a concrete check: a threshold, a reproduced number, or a negative test that must fail. Never "it looks right."
3. **Do not trust the confident answer.** Every build scores the AI and reports where it was wrong as a real number.

## The three tiers

- **Foundation**: the fundamentals, drilled. Not the easy projects, the load-bearing ones.
- **Core**: the same fundamentals under real pressure, where the tradeoffs bite and the answer stops being obvious.
- **Advanced**: problems with no clean answer, where you choose, defend the choice, and live with it.

## The systems

Each system here is one 45-minute build, rendered with its architecture diagram, a numbered implementation map, and the check that proved it works. Browse the full catalog in [`INDEX.md`](./INDEX.md).

- **[Your First Rep: Ship a Global-Problem Card Through GitHub](./systems/first-rep-github/)**: the delivery loop drilled once, a sourced and honest one-page card shipped through a repo, a board, a pull request, and a tagged release. The warm-up every later build reuses.
- **[Testable Multi-Provider Network Module](./systems/testable-multi-provider-network-module/)**: a reusable network module with tests that prove it and a one-page decision record on the infrastructure tool, ready for the architecture board.
- **[Error Budget Control Room: Prove a Page Is Worth Waking Someone](./systems/error-budget-control-room/)**: service level objectives turned into an error budget that decides whether a page is worth waking someone, proven against a replayed incident.
- **[The Delivery Scoreboard: Four Keys From Your Own Repo](./systems/delivery-scoreboard/)**: the four delivery keys computed from your own git history, with an honest line on what each number does not prove.
- **[Spec-Driven Feature Factory](./systems/spec-driven-feature-factory/)**: a written spec becomes the source of truth, the agent builds from it, and you review the plan instead of squinting at a diff.
